# 1. The constant "names" such as #LED_GPIO_PIN are replaced with

#    ldr     r0, [pc, #36]   ; (0x100003e4 <led_set_state+8>)
#    the reason is because the opcode is only 250 long and so it puts it closely
#    by having a pc and incrementing 36 (since of the restriction).
#    where as our written assembly gives the offset a name, SLEEP_TIME which

# 4. Before every instruction in gdb, the address is visible

#    where as in our written assembly we must look at the registers itself.
# 5. The comments use the ; syntax, where ours uses the @ syntax, it does not 
#    actually matter, and we are allowed to use ;, however this is a difference and
#    so I will note it here.
# 6. When branching to the label loop:, in our written assembly we use `b` syntax
#    where as gdb uses `b.n` syntax
# 7. Before branching to the address it hard codes in, in gdb, it gives you the name
#    of the branch branching to (inside the <>) e.g. bl 0x100003ca <sub_toggle>
#    In our written assebmly it is just the name of the function e.g. bl sub_toggle
